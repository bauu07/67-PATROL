FUNDAMENTOS DE CALIDAD • QA & QC

Gestión y Estándares de Calidad

Comprende los pilares fundamentales del aseguramiento de calidad de software, métricas clave y la evolución de los estándares internacionales de evaluación.

Conceptos Clave: QA vs. QC

En la ingeniería de software moderna, la calidad no es una coincidencia, sino el resultado de procesos disciplinados. Es fundamental distinguir entre dos disciplinas complementarias:

Quality Assurance (QA)

Enfoque preventivo orientado a los procesos. Su objetivo es establecer normas, revisiones de código y metodologías para evitar que los defectos aparezcan durante el ciclo de vida del desarrollo.

Quality Control (QC)

Enfoque detectivo orientado al producto. Involucra la ejecución de pruebas funcionales, estructurales y de integración para identificar y corregir errores antes de entregar el software al usuario final.

Métricas Clave de Software

Para gestionar la calidad de manera objetiva, los equipos de desarrollo utilizan indicadores cuantitativos (métricas):

  • Densidad de Defectos: Cantidad de errores detectados por cada KLOC (Kilo Líneas de Código) o tamaño funcional.
  • Cobertura de Pruebas (Test Coverage): Porcentaje del código fuente ejecutado durante las pruebas automatizadas.
  • MTBF (Mean Time Between Failures): Tiempo promedio de operación sin fallos críticos en producción.
  • Complejidad Ciclomática: Métrica de la complejidad lógica de un programa para estimar el esfuerzo de prueba requerido.

Estándares Internacionales de Calidad

Los modelos de calidad proporcionan un marco estructurado para evaluar las características internas y externas de un producto de software. Utiliza las pestañas a continuación para comparar la evolución normativa:

ISO/IEC 9126 (Modelo Clásico)

Estándar histórico publicado en 1991 que estableció por primera vez un marco integral para evaluar la calidad del software dividiéndola en 6 características principales:

1. Funcionalidad: Cumplimiento de propósitos explícitos e implícitos.
2. Confiabilidad: Capacidad de mantener un nivel de rendimiento especificado.
3. Usabilidad: Facilidad de aprendizaje, operación y atractivo para el usuario.
4. Eficiencia: Relación entre el desempeño y los recursos utilizados.
5. Mantenibilidad: Facilidad para realizar modificaciones y correcciones.
6. Portabilidad: Capacidad del software para ser trasladado a otro entorno.

ISO/IEC 25000 - SQuaRE (Modelo Actual)

System and Software Quality Requirements and Evaluation. Es la evolución moderna que reemplaza a la ISO 9126. Organiza la evaluación en 5 divisiones clave para un control integral:

ISO 2501n (Gestión de Calidad): Modelo de calidad del producto y del uso.
ISO 2502n (Medición de Calidad): Métricas internas y externas del software.
ISO 2503n (Requisitos de Calidad): Especificación de metas de calidad.
ISO 2504n (Evaluación de Calidad): Guías y soporte para el proceso de evaluación.

TÉCNICAS DE ASEGURAMIENTO DE LA CALIDAD

Estudio analítico de los niveles de pruebas estructurales y tipos de validación (Caja Negra y Caja Blanca) en la Ingeniería de Software.

Niveles de Pruebas de Software

Pruebas Unitarias

Evaluación de componentes individuales, funciones, métodos o clases de código de forma completamente aislada del resto del sistema.

QA Level 01

Pruebas de Integración

Verificación de la comunicación, sincronización e intercambio de datos correcto entre diferentes módulos interconectados o bases de datos.

QA Level 02

Pruebas de Sistema

Evaluación global del software completamente integrado para validar que se comporta de acuerdo con los requerimientos funcionales y no funcionales.

QA Level 03

Pruebas de Caja Negra (Black Box)

Se centran en las entradas y salidas del sistema sin conocer la estructura interna o el código fuente. Evalúan la funcionalidad desde la perspectiva del usuario final.

  • Pruebas funcionales y de usabilidad.
  • Partición de equivalencia y valores límite.
  • Pruebas de aceptación de usuario (UAT).

Pruebas de Caja Blanca (White Box)

Examinan la estructura interna del código fuente, flujos lógicos, condiciones y coberturas. Requieren conocimientos avanzados de programación.

  • Cobertura de sentencias y ramas de código.
  • Análisis de caminos de ejecución.
  • Revisión de seguridad e insumos de código.

US-04: Herramientas de Calidad y Gestión (Grilla Completa)

Catálogo extendido de herramientas clave para el seguimiento de defectos, análisis estático, gestión de pruebas y automatización. Usa los filtros para ver elementos individuales o todos a la vez:

Jira / Trello

Plataformas líderes de gestión de incidencias y tableros ágiles para registrar, asignar tareas y monitorear el ciclo de vida completo de los bugs de software.

Bug Trackers

GitHub Issues / GitLab

Sistemas integrados de seguimiento de errores directamente vinculados a los repositorios de código fuente y pull requests del equipo de desarrollo.

Bug Trackers

ESLint / Prettier

Herramientas de análisis estático de código para JavaScript/TypeScript enfocadas en estandarizar la sintaxis y detectar errores lógicos antes de compilar.

Linters / Análisis Estático

SonarQube

Plataforma exhaustiva para la inspección continua de la calidad del código, midiendo deuda técnica, vulnerabilidades de seguridad y duplicidades.

Linters / Análisis Estático

TestRail

Software especializado en gestión de pruebas para planificar escenarios de QA, organizar carpetas de test cases y registrar resultados de ejecución.

Test Management

Postman

Entorno de pruebas y desarrollo enfocado en la validación funcional, contrato y rendimiento de servicios web y APIs REST.

Test Management

Selenium / Cypress

Frameworks de automatización de pruebas end-to-end (E2E) para interfaces web, permitiendo simular interacciones reales de usuarios en múltiples navegadores.

Automation Testing

Jest / JUnit

Librerías de pruebas unitarias robustas para entornos JavaScript y Java, optimizadas para verificar la precisión lógica de componentes aislados de código.
