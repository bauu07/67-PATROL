MÓDULO 01 // MARCO TEÓRICO Y NORMATIVO

EVOLUCIÓN NORMATIVA: ISO 9126 VS. ISO 25000 (SQuaRE)

ISO/IEC 9126 (1991-2001)

LEGADO CLÁSICO

Estableció el primer modelo formal de calidad del software estructurado en 6 características troncales aplicadas tanto a la evaluación interna como externa del producto.

Características: Funcionalidad, Fiabilidad, Usabilidad, Eficiencia, Mantenibilidad, Portabilidad.

ISO/IEC 25000 SQuaRE

ESTÁNDAR MODULAR

Reemplazo moderno que unifica criterios mediante un sistema de divisiones (2500n a 2504n), integrando explícitamente la Seguridad y la Compatibilidad.

Gestión de Calidad: 2500n
Modelo de Calidad: 2501n
Medición y Requisitos: 2502n-3n

QA vs. QC vs. Testing

GOBIERNO QA

Delimitación estricta de dominios para optimizar la gobernanza del ciclo de vida del software (SDLC) y evitar la superposición de roles operativos.

QA: Proceso preventivo sistémico.
QC: Verificación de calidad del entregable.
Testing: Ejecución y detección de fallos.
MÓDULO 02 // INGENIERÍA CUANTITATIVA

MÉTRICAS DE CÓDIGO Y EFICIENCIA DE DEFECTOS (DRE)

Complejidad Ciclomática V(G)

McCabe (1976)

Mide la complejidad estructural cuantitativa del código fuente contando el número de caminos linealmente independientes a través del grafo de flujo de control.

V(G) = E - N + 2P
● 1–10: Código estructurado, bajo riesgo.
● 11–20: Complejidad moderada, riesgo medio.
● > 50: Código altamente inestable y propenso a fallos.

Eficiencia de Detección (DRE)

EFICACIA QA

Evalúa la capacidad del equipo de desarrollo y QA para capturar errores antes de que el software sea liberado al entorno de producción.

DRE = B / (B + C) * 100%
Donde B = Errores detectados antes de entrega, C = Errores reportados por producción.

PIRÁMIDE Y NIVELES DE PRUEBAS DEL SOFTWARE

Nivel de Validación
Alcance y Componentes
Herramientas Estándar
Objetivo Técnico Principal
NIVEL 01 Pruebas Unitarias
Funciones, métodos, clases y algoritmos individuales aislados.
JUnit, Jest, PyTest, NUnit
Verificar la corrección lógica elemental de fragmentos mínimos.
NIVEL 02 Pruebas de Integración
Comunicación entre módulos, llamadas REST APIs y bases de datos.
Postman, REST Assured, Testcontainers
Garantizar la sincronización y transferencia correcta de datos.
NIVEL 03 Pruebas de Sistema (E2E)
Flujos de usuario completos simulados en interfaces gráficas/navegador.
Cypress, Playwright, Selenium
Validar el comportamiento integral emulando interacciones reales.
NIVEL 04 Pruebas de Aceptación (UAT)
Validación de criterios de negocio funcionales junto al cliente o PO.
Cucumber, SpecFlow, Criterios BDD
Certificar formalmente que el sistema satisface las metas operativas.
